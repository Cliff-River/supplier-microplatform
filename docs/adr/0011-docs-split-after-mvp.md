# ADR-011 文档拆分在 MVP 后实施

- 状态：已采纳
- 生效版本：MVP v1.0
- 关联需求：13.2

## 背景

开发期将架构、数据模型、API、页面设计拆散到多个文件，容易出现文档与需求不同步、上下文丢失。但长期维护又需要模块化文档。

## 备选方案

1. 开发前立即拆分 `docs/*`。
2. 开发期以 `requirements.md` 为单一事实来源，MVP 完成后再拆分。

## 决策

采用方案 2。MVP 完成后按以下结构拆分，主文件保留需求与索引：

- `docs/architecture.md`：总体架构、请求链路、权限、状态机、存储与邮件。
- `docs/data-model.md`：表、枚举、关系、一致性规则、迁移。
- `docs/api.md`：接口清单、响应包络、错误码。
- `docs/pages.md`：信息架构、页面清单、路由守卫。
- `docs/adr/`：每条 ADR 独立文件。

## 影响

- 正面：开发期上下文集中；交付后文档可维护。
- 负面：拆分后需持续同步代码与文档；以 ADR 记录决策变更。
